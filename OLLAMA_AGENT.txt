### 5. CONSISTENCY ENFORCEMENT

## 🔢 TOKEN TRACKING METHOD

### 1. What to Track

Track three values separately:

- **Input Tokens:** Tokens sent to the model (system prompt, instructions, context, and user messages).
- **Output Tokens:** Tokens generated by the model.
- **Total Tokens:** Input Tokens + Output Tokens.

### 2. Source of Token Data

**When using Ollama:**
- Retrieve actual token counts from the API response.
- Use `prompt_eval_count` for input tokens.
- Use `eval_count` for output tokens.
- Calculate total usage by adding both values.

**When using Custom GPT or another interface:**
- Use actual usage statistics if available.
- If exact token counts are unavailable, report usage as "Not available".
- Never present estimates as verified measurements.

### 3. Budget Calculation

Configured tracking budget: **34,000 tokens**.

Calculate:

`Remaining Tokens = 34,000 - Cumulative Tokens Used`

`Budget Used (%) = (Cumulative Tokens Used / 34,000) × 100`

Treat 34,000 as a tracking budget, NOT as a guaranteed model context-window limit.

### 4. Tracking Rules

- Record input and output tokens after each completed generation.
- Maintain cumulative totals across production batches.
- Do not count the same API response twice.
- Do not assume token usage based on word count.
- Clearly distinguish measured usage from estimated usage.
- If usage data is unavailable, do not update the verified total.

### 5. Reporting Format

```text
TOKEN USAGE REPORT

Input Tokens:       [X]
Output Tokens:      [X]
Total Used:         [X / 34,000]
Remaining:          [X]
Budget Used:        [X%]
Data Source:        [Ollama API / Other / Unavailable]
Measurement:        [Verified / Estimated / Unavailable]
```
